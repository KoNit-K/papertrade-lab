# Papertrade Mechanics Lab

**研究 Papertrade 的交易、结算与 PAPER 机制。**

这是一个独立的开源研究项目。我们阅读官方文档，分析公开前端、历史合约字节码、
交易输入和事件，把 Papertrade 的规则拆成可以追踪证据、核对版本和逐步复验的解释。
重点是弄清楚：一笔交易如何执行，盈亏如何进入余额或待赔付债权，PAPER 又如何产生。

## Papertrade 的机制是什么样的？

下面区分**官方文档描述**、**用户操作观察**与**字节码／事件研究**。文档中的经济规则尚未完成独立结算复验，
不能把当前说明或某次区块快照直接套用到所有历史交易。

### 交易意图如何变成合约执行

官方架构把用户签署的交易意图交给 relayer，再由 BatchExecutor 批量调用 Exchange。
因此，意图被接收、交易被打包、某条调用成功，是不同阶段。等待交易执行也不同于等待盈利赔付。
见[架构来源](https://docs.papertrade.xyz/how/architecture/)。

```mermaid
flowchart LR
    A[用户交易意图] --> B[Relayer]
    B --> C[BatchExecutor 批量执行]
    C --> D[Exchange 仓位与账本]
    D --> E[余额或待赔付债权]
```

这是官方文档中的路径。我们已在一个历史候选中观察到批处理内的平仓调用，
其仓位 ID 与平仓事件一致；完整的意图授权和经济结果仍需更多证据。

### 合约交易模式：独立逐仓，开仓后整仓结束

Papertrade 的交易对手是协议 LP，交易是合成杠杆头寸；它引用 Hyperliquid 的价格，
不代表替用户在 Hyperliquid 开了一个永续仓位。以下是官方文档的产品规则，
不是我们已经完成的历史合约复验。

| 项目 | 规则与边界 |
|---|---|
| 全仓／逐仓 | 每笔仓位独立承担保证金，没有全仓共享保证金，也没有全仓／逐仓切换。 |
| 给原仓加仓 | 原仓开出后不能修改。想增加同方向敞口，可以另开一个独立仓位，不会合并到原仓。 |
| 追加／抽取保证金 | 均不支持；不能靠补保证金推迟原仓清算。 |
| 修改杠杆 | 开仓时选择，开仓后不能调整。 |
| 减仓／部分平仓 | 不支持；主动关闭是整个仓位。多笔独立仓位可分别关闭。 |
| 市场与上限 | 文档列出 BTC、ETH，最高 1000×，单仓名义价值（保证金 × 杠杆）上限 1000 万美元；这些不是所有历史时点的固定参数。 |
| 成交方式 | 开、平仓按执行时的 BBO 中间价结算，LP 是对手方；当前研究未核实限价单、止盈止损等额外订单功能。 |
| 清算 | BBO 达到 bust price 后可触发硬清算，损失该仓全部逐仓保证金；它与主动平仓的剩余权益计算不同。 |
| 费用 | 文档描述无资金费、无按名义本金收取的交易费、无用户支付的 gas；盈利有收益调整和费用，亏损分支也可能从 LP 所得中分出费用。 |

来源：[交易与保证金](https://docs.papertrade.xyz/learn/trades-pricing/)、
[FAQ](https://docs.papertrade.xyz/intro/faq/)、[清算](https://docs.papertrade.xyz/learn/liquidations/)。
页面标注更新于 2026-10-06，本项目读取于 2026-10-21。
匿名操作观察“只能逐仓、不能给原仓加仓、开了只能整仓关”与这些说明一致；
这一观察没有可核验的前端版本或交易记录，不据此推定所有历史实现。

字节码研究也发现仓位按 ID 保存独立保证金、杠杆和开关字段，平仓输入按仓位 ID 列表处理。
但默认 RPC 的代码／存储读取仅支持最新状态：此前带历史区块号的响应不能证明历史版本，
完整历史状态和权限仍需补齐。见[状态证据审计](docs/research-notes/004-economic-path-and-state-audit.md)。

### 盈利到账不是固定扣一个百分比

官方文档描述的盈利路径包含 deadband、非线性收益调整，以及对调整后收益收取的费用。
其中的启动参数 `10%` 不等于每笔盈利都固定扣除 `10%`；文档描述的 `2%` 费用也有自己的计费基数。
要解释到账金额，需要分开看价格变化、deadband 后盈亏、调整后盈亏、费用、返还保证金和实际可用余额。
第 4 条候选的这些金额已完成同案整数一致性检查，但执行价格来源与历史参数尚未独立证实，不能称为结算复验。
详见[盈利到账研究](docs/research-notes/001-winning-trade-payout.md)。

### 现金、债权和赔付队列是不同的账

官方偿付说明区分可用现金和待赔付债权，并描述资金不足时的排队支付，以及使用债权开仓的不同分支。
因此，“记账上应得多少”和“现在可以取出多少”不能混为一谈；是否已经付款，需要结合账本与后续事件判断。
文档中的最终支付描述也不能当作固定到账期限。见[偿付与队列来源](https://docs.papertrade.xyz/how/solvency-queue/)。

### PAPER 发行要看合格亏损和曲线状态

官方发行说明把 PAPER 与合格亏损、tracked LP 和高水位进度联系起来。
某一时点的边际发行率，与整笔亏损对应的平均发行率，是两个不同量。
研究“为什么每单位亏损得到的 PAPER 变少”时，还需要核对发行基数、区间和单位，不能只比较两个页面数字。
见[发行曲线来源](https://docs.papertrade.xyz/how/mint-curve/)。

### 开多、开空和清算受各自条件约束

官方风险文档描述了方向性持仓容量、市场开关、杠杆和仓位限制。
界面、中继接收规则和合约执行检查是不同层次；某次单边开仓失败，仍需当时的参数、状态和错误证据才能解释。
见[风险来源](https://docs.papertrade.xyz/how/risk/)与[机制地图](docs/mechanism-map.md)。
